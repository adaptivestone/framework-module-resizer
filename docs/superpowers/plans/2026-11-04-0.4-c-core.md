# 0.4.0 phase C: core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A media store that loses what the worker wrote fails visibly, a dimension backfill cannot land on a swapped original, preview rows stop getting an unstable `_id`, and a host can delete replaced files from a hook (design rulings C1 to C4; C5 is a decision to drop).

## Review Focus

1. **Hydrated Mongoose rows as the reload.** Fields are read through sub-document getters, with a namespaced ref, a fit row and a filtered row, on a first render and on a replacement: no false dead-letter (Task 1 test `hydrated rows raise no RESIZE_MEDIA_ROW_NOT_KEPT…`).
2. **A read-back row without a ref, and a ref JSON cannot encode (a BigInt).** The check must not throw a `TypeError`, which would be retried with a useless message (Task 1 test `rowsNotKept: a read-back row without a ref…`).
3. **A schema with `strictQuery: 'throw'` or `true` and an undeclared dimension.** The new filter must not add a `StrictModeError` to a task that worked, and a stored pair must stay (Task 2 tests `strictQuery: …`).
4. **A row replaced under 0.3.0, with no stored `_id`.** It reads a random id on each load, renders nothing when read, and stores a real id when it is next replaced (Task 2 test `a row replaced under 0.3.0…`).
5. **A host's `onPreviewReplaced` tap that throws, and a write that removed more than the stale row.** The task still completes, the next tap runs, and every removed row is reported (Task 3 tests `a tap that throws…`, `every row the write removed…`).
6. **A store whose own answer already lacks the field it lost.** `rowsNotKept` must see the rows the recorder left out, or the store loops with no `RESIZE_MEDIA_ROW_NOT_KEPT` (Task 1 test `a store that answers with the rows as it stored them…`).
7. **A driver that names files by their bytes.** A ref a new row keeps must reach neither `onPreviewReplaced` nor `generate().replaced`, while the swap in the caller's `media.previews`, which goes by identity, is untouched (Task 3 test `a replacement that keeps the ref…`).

## Rulings

Each: what, why, cost if wrong.

1. **The group check names the fields of the closest row: the group's row with the fewest differences in what a read finds a row by (`sizeKey`, `format`, `resizer`, `pipeline`, filters), then the fewest differences, then a matching `identity`, then the first.** A list of "fields no row of the group holds" can come out empty when each field is held by a different row. Read fields come first because `identity` no longer decides a task (ruling 6): another size key's row under one ref differs in one field too. `identity` still breaks the tie it leaves: a store losing `format`, `filters` or `pipeline` ties with that row, and would name `sizeKey`. Cost: wording of a message, on a store that lost `identity` too.
2. **`rowsNotKept` is an internal export of `src/previewRecorder.ts`, not of the package.** That file owns `describeRef` and "what the store kept". Cost: one move.
3. **`ResizeSetupError`, thrown before the coverage check.** A store that loses fields is wiring, and no retry fixes it, so it wins over the retryable `RESIZE_WORKER_INCOMPLETE` in the same attempt. Cost: none known.
4. **A false alarm stays possible on a content-addressed store, accepted.** A reload that lags and shows another row under the same ref (an older row after a replacement, naming `encodeSig`; another size key's row on a first render, naming `sizeKey`; or a concurrent worker with other settings rewriting equal bytes) has rows under the ref and none matching, so the task dead-letters. Its rows are stored; the cost is one `error` line and one cooldown. Excluding rows the first load already held would close it, but by reasoning (not run) it reopens the silent loop C1 exists to stop: a store that loses a field on equal bytes reads back what the first load held, so its second task would pass. One rare case joins it through ruling 16: a store left a row out because of a lagging reload, on a content-addressed driver, with another row under the same ref. Cost, for both: a misleading line for a custom store on lagging reads, and one cooldown.
5. **Worker only.** `generate()` does no reload today, and C1 says "after the worker's reload". A test pins that it does not throw. Cost: an eager-only host with a bad store keeps its silent loop, which needs an explicit `generate()` per render anyway.
6. **A custom store with no `identity` column, or its own form of it, keeps working, and gets one warning.** Overturned in Task 1's review. Measured: a table store keyed by the computed identity, with `identity` absent, `null` or in its own form, reads fresh, yet every first render was dead with an `error` line, and the cooldown then blocked a replacement. The 0.3.0 contract told such a store the core "never reads a stored `identity` string", and upgrading must not start dead-lettering a store that works. So `identity` is not among the fields that dead-letter. A kept row whose `identity` is absent or differs logs one `warn` per Resizer, because `invalidate()` finds such rows only by identity, so it leaves them, and a `replacePreviews` that removes by stored identity leaves them too (a store keyed by the identity it computes replaces fine). Cost: a store that relies on those calls learns it from one line, not a failure.
7. **The backfill passes `strictQuery: false`, the option `MongoLockStore` already passes.** Measured: a schema with `strictQuery: 'throw'` and an undeclared dimension gets a new `StrictModeError` without it, where it only dropped the dimensions before. Other model shapes may ignore the option. Cost: one more optional key in `MongoMediaUpdateOptions`.
8. **The filter is built inline on each call, not as a module constant.** Mongoose casts `$or` in place. Cost: none.
9. **A custom store is told to write dimensions only while the pair is absent, not forced.** There is no signature change, and one that writes unconditionally behaves as today. `docMedia` mirrors the new rule so tests see what `MongoMediaStore` does. Cost: none.
10. **`onPreviewReplaced(removed: Preview, ctx)`, once per removed row, after the `onPreviewGenerated` loop, with `ctx` `{}`, from `#renderPending`.** So it fires from the worker and from `generate()`, and it still reports when `generate()` goes on to throw. It does not fire for `invalidate()`, which returns its refs, or for `persist: false`, which writes nothing. Cost: a host that deletes both `result.replaced` and in the hook deletes twice, harmlessly.
11. **A removed row whose ref the same write stored again is not reported, by `onPreviewReplaced` or by `generate().replaced`.** `#renderPending` filters `removed` with an exported `describeRef` against the rows it just wrote, so this needs no read. Deleting a ref the store still points at would lose a live file, an anti-goal: after a settings or version change on a driver that names files by their bytes, the preview is fresh and never regenerates. A ref another size key of the same media still holds (two size keys with equal bytes, one of them outside this write) is still reported: seeing that needs a read, and the docs say so. Cost: that driver uses a sweep.
12. **The `resize: replaced … outdated preview(s)` log line stays.** Hooks can be lost in a crash; the line is written first. It still names a ref a new row kept, and the docs say so. Cost: none.
13. **C1 also compares `resizer` and `pipeline` (through `previewScope`, with their defaults) and the filter signature (`getFilterSig`).** A read finds a row by these (`storedPreviewRows` in `src/images.ts`), not by the stored `identity`. Measured: a custom store that loses `pipeline` or `filters` otherwise loops silently, `completed` on every window, one upload each, nothing served, no `warn` or `error` line. This widens design ruling C1, so the design's C1 row gets one sentence, which Task 1 commits. Cost: a store that rewrites `filters` values dead-letters, and its reads would miss those rows anyway.
14. **`RESIZE_MEDIA_ROW_NOT_KEPT` stays `retryable: false`, as the one stated exception to the rule for `false`.** The rule counts a later delivery after a deploy, and a deployed store fix would help. But no retry can succeed until a host fixes its store, and each one costs a render, an upload and an orphaned file: `true` would keep the expensive loop this exists to end. `AGENTS.md`, the README and the comment on its row in `src/retryable.test.ts` state the exception, so nobody "fixes" it. Cost: after the fix a media only `prewarm()` queues needs `prewarm()` again (by reasoning, not run); reads queue theirs after the cooldown.
15. **The docs say to delete after the longest cache time.** A tap that deletes at once breaks URLs in responses built before the write and in CDN caches, where `S3Storage` uploads live for a year. The README and the guide say so. By reasoning, not run. Cost: one sentence.
16. **The check runs over `written`: `generated`, plus the rows the recorder left out while the store holds no row of their identity.** A store that answers with the rows as it really stored them has already lost `sizeKey` or `format` in its answer. Measured over `generated` alone: 15 uploads in three cooldown windows, and no `RESIZE_MEDIA_ROW_NOT_KEPT`. `alreadyStored` and `blocked` rows stay out. So a store that answers `[]` and loses a signature is seen at its second attempt, not its first: attempt 1 finds its own row, with other signatures, and takes it for another worker's (`blocked`), and attempt 2 replaces that row and is dead, after two uploads. Intended, and pinned in `src/regenerate.test.ts`. Cost: ruling 4's rare case, and that one extra upload.
17. **The backfill's filter takes `$type: ['double', 'int', 'long']`, not `'number'`.** `'number'` also matches Decimal128, which `storedDims()` cannot read, so a Mixed original holding one would stay without usable dimensions for good. Cost: none known; a pin in `src/framework/stores.test.ts`.
18. **`verify()` also requires `sizeKey`, `format`, `contentType` and `storageRef` on strict rows, and not `resizer`, `pipeline` or `filters`.** A strict row schema without the first four can never serve a row (a read finds a row by `sizeKey` and `format`, and `isUsablePreview` requires `contentType` and `storageRef`), so failing at start beats a dead first task. A shape of nested paths counts as declared for `storageRef` only, the driver's own object. It must declare every key of the driver's ref, which `verify()` cannot tell (measured on `LocalFsStorage`: a nested `{ key }` passes, the task ends `completed,1`, and a read gives `ready 0, missing 0` with an `error` line); the docs say so. `contentType` also joins the check, on loss only: a read needs one and takes any, so a store's own form of it still works (measured: such a row reads fresh). The other three have defaults: a host on the `default` Resizer and pipeline with no filters runs fine without them, and one that needs them gets a dead task that names them. Cost: that host learns it at its first task.
19. **The check cannot fail a task whose work is done.** Measured: a ref whose JSON and `String()` both throw, on any row of the media, took a task from `completed` at attempt 1 to `dead` at attempt 5 with a raw `TypeError`. A row or a ref that cannot be read is skipped, nothing is read when nothing was written, and an unexpected throw logs one `warn` per Resizer while the task keeps its result. Cost: a real loss on a hostile row goes unnoticed for that task.
20. **A row back with no `storageRef`, every compared field as written, names `storageRef`.** Nothing is under the written ref, so the group rule alone reads this as a lagging reload, and the store loops. Matching on what a read uses alone was too wide. Measured: an old ref-less row (a 0.2.x flat `key`/`bucket` row that 0.3.0 left unmigrated) of the same size and format took a healthy `MongoMediaStore` from `completed,1` to `dead,1` when `invalidate()` landed between write and reload or another worker replaced under its own ref, and a custom store that reshapes refs too. Such a row has no signatures, so it no longer counts. Cost: a store that loses `storageRef` and a compared field together is not named by this rule.
21. **A replaced row stores an `_id` exactly when an appended one would. This overrides design C3 as first written, Task 2's brief and the earlier `_id: false` and `auto: false` forms of this ruling.** The fragment keeps its default `_id`, so `row._id` behaves and is typed as in 0.3.0. `replacePreviews` puts an id on each row it writes, because Mongoose casts `$push` and generates one, and does not cast an update pipeline. The id is what `$push` would give: a new `model.base.Types.ObjectId` for the schema's automatic `_id`, or the default of a declared `_id`. No id is written under `_id: false`, `auto: false`, a declared `_id` with no default, a Mixed or plain `previews` array, or a model-shaped object without `schema`. Why not rows without an id, measured on mongoose 9.0.0 and 9.11.4, with no error and compiling on both hosts: under `_id: false`, every removal by the id of an older row removes every row. Under `auto: false`, on a new row, `Model.updateOne(…, { $pull: { previews: { _id: row._id } } })` and `findByIdAndUpdate` remove every row without an id, `previews.remove({ _id: row._id })` and `previews.pull({ _id: row._id })` remove every row, and `splice(findIndex(String(_id) === …))` removes the wrong row. With a stored id each of these removes that row alone. A row replaced under 0.3.0 keeps its random hydrated id until it is next replaced: nothing migrates it, and reading it renders nothing. Cost: about 12 bytes per replaced row, plus the write path.

/** A store that loses `field` from the rows it stores, and answers with the rows it was given. */
const losing =
  (field: keyof Preview, only: (row: Preview) => boolean = () => true) =>
  (inner: ReturnType<typeof docMedia>): MediaStore => {
    const strip = (rows: Preview[]): Preview[] =>
      rows.map((row) => {
        if (!only(row)) {
          return row;
        }
        const { [field]: _lost, ...rest } = row;
        return rest as Preview;
      });
    return fakeMedia({
      load: (id) => inner.loadMedia(id),
      appendPreviews: async (id, previews, dims) => {
        await inner.appendPreviews(id, strip(previews), dims);
        return previews;
      },
      replacePreviews: async (id, identities, rows) => {
        const { removed } = await inner.replacePreviews(id, identities, strip(rows));
        return { stored: rows, removed };
      },
    });
  };

/** Upload the png as the original of media m1, with no previews stored yet. */
async function bareMedia(w: ReturnType<typeof world>, r: Resizer): Promise<MediaLike> {
  const original = await r.uploadOriginal({ body: png, visibility: 'private' });
  const doc: MediaLike = { id: 'm1', original, previews: [] };
  w.docs.set('m1', doc);
  return doc;
}

/** The errors of the tasks `r` dead-letters from now on. */
function deadErrors(r: Resizer): ResizeError[] {
  const errors: ResizeError[] = [];
  r.hook('onTaskDeadLettered', (_task, err) => {
    errors.push(err as ResizeError);
  });
  return errors;
}

const statuses = (w: ReturnType<typeof world>) =>
  w.tasks.rows.map((row) => [row.status, row.attempts]);

/** Storage that names a preview by its bytes: equal bytes give one ref. */
function contentAddressed(w: ReturnType<typeof world>): void {
  const upload = w.storage.upload.bind(w.storage);
  w.storage.upload = (args) =>
    upload({
      ...args,
      key: `previews/${createHash('sha256').update(args.body).digest('hex')}`,
    });
}

// Both boxes are larger than the 64×64 source, so both previews are the source at its own size:

const KEPT_FIELDS = ['identity', 'origin', 'encodeSig', 'sizeKey', 'format'] as const;
export type KeptField = (typeof KEPT_FIELDS)[number] | 'resizer' | 'pipeline' | 'filters';

export function rowsNotKept(written, readBack) {
  const groups = new Map<string, Preview[]>();
  for (const row of readBack ?? []) {
    // A row without a locator says nothing about a write.
    if (row?.storageRef == null) continue;
    // push onto groups[describeRef(row)]
  }
  const notKept: RowNotKept[] = [];
  for (const row of written) {
    let closest: KeptField[] | undefined;
    for (const candidate of groups.get(describeRef(row)) ?? []) {
      const fields: KeptField[] = KEPT_FIELDS.filter((f) => candidate[f] !== row[f]);
      // A read finds a row by these too, with their defaults: a store that loses one makes that
      // read miss the row, whatever `identity` says.
      const [held, wrote] = [previewScope(candidate), previewScope(row)];
      if (held.resizer !== wrote.resizer) fields.push('resizer');
      if (held.pipeline !== wrote.pipeline) fields.push('pipeline');
      if (filterSig(candidate) !== filterSig(row)) fields.push('filters');
      if (!closest || fields.length < closest.length) closest = fields;
    }
    // No group: nothing to judge. An empty list: some row of the group matches.
    if (closest && closest.length > 0) {
      notKept.push({ identity: String(row.identity), fields: closest });
    }
  }
  return notKept;
}
