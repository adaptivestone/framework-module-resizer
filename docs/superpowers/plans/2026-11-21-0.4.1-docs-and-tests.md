### Task 1: The two timing-dependent tests

**Files:**
- Modify: `src/regenerate.test.ts:2943-2983` (the `for (const hook of ['onPreviewGenerated', 'onPreviewReplaced'] as const)` loop with the two "tap that outlasts taskTimeoutMs" tests)

**Interfaces:**
- Consumes: `world()` (same file, `:89-142`): `w.storage`, `w.tasks.rows`, `w.seed`, `w.resizer`, `w.read`, `w.work`.
- Produces: nothing other tasks use.

- [ ] **Step 1: Make the failure deterministic.** In both tests, after `resetResizerForTests()` and before `w.read(r, doc)`, wrap `w.storage.download` so that its FIRST call after the seed waits 300 ms before delegating. This is the work before the variant pool that, under load, outlasts the 100 ms timeout. Keep `taskTimeoutMs: 100` and the 400 ms `setTimeout` tap for now.

- [ ] **Step 2: Run them and see them fail.**
  Run: `node --experimental-strip-types --import ./src/testHelpers/noAws.ts --test --test-name-pattern="outlasts taskTimeoutMs" src/regenerate.test.ts`
  Expected: FAIL. The maxAttempts-2 tests end `dead` instead of `completed`. The maxAttempts-1 tests fail on `decision.ready.length` (no row was stored), or on `stale`.

- [ ] **Step 3: Remove the dependence on timing.**
  - Set `taskTimeoutMs: 2000` in both tests.
  - Replace the 400 ms tap with one that waits on a promise the test resolves in a `finally` around `await w.work(r)`, so the tap always outlasts the timeout and leaves nothing pending after the test.
  - In the tap, record `w.tasks.rows[0].attempts` at its first call.
  - Keep the 300 ms delay from Step 1.

  Assertions:
  ```ts
  // both tests
  assert.equal(attemptsAtFirstCall, 1); // delivery 1 reached the tap, so its rows were stored before its timeout
  // maxAttempts 1 test, unchanged otherwise
  assert.equal(row.status, 'dead');
  assert.match(String(row.error), /exceeded taskTimeoutMs/);
  // maxAttempts 2 test, unchanged otherwise
  assert.equal(row.status, 'completed');
  assert.equal(row.attempts, 2);
  assert.equal(calls, 1);
  ```

- [ ] **Step 4: Run them and see them pass, then repeat.**
  Run the Step 2 command, then the same command 10 times in a loop.
  Expected: every run passes (4 tests each).

- [ ] **Step 5: Gate and commit.**
  Run: `npm test && npm run check && npm run types:check`
