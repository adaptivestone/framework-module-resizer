# 0.4.0 Phase A: Signals Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** an operator can see why a task failed, a damaged original fails once and visibly instead of producing a garbled preview, `retryable` means what it says, and a read or a boot reports the wiring mistakes that today stay silent.

**Architecture:** no new moving parts. `Consumer` writes its own failure lines. One helper, `src/helpers/sharpError.ts`, reads the engine's messages for the decoders and the uploader. `limits.failOn` and `upload.verify` are new image settings. `MongoTaskQueue.add` reads before it inserts. The rest is changed defaults, codes and log lines.

**Tech Stack:** TypeScript (ESM, Node >= 24 with `--experimental-strip-types`), `node:test`, biome, Sharp 0.35.5, Mongoose 9, mongodb-memory-server.

**Spec:** `docs/design/2026-11-04-0.4.0.md`, rulings A1 to A14. Measurements and prototypes: `.superpowers/sdd/2026-11-04-0.4.0/research/` (`research-operate.md`, `research-adopt.md` section 10, `research-core.md` items 4, 7, 8, 10). Where this plan differs from the research, the plan is right.

## Rulings

Each: what was decided; why; what it costs if wrong.

1. **The recogniser reads one line: the first that is not `source: bad seek to N`, after removing the `Input buffer has corrupt header:` prefix.** Measured on Sharp 0.35.5: a healthy HEVC HEIC on the prebuilt build says `source: bad seek to 1024\n…\nheif: Error while loading plugin: Support for this compression format has not been built in: HEVC (…) (11.6003)`, so a first-line match, or the research's regex, would dead-letter a good photo as damaged. If wrong: a damaged file with an unusual message costs five attempts.
2. **Words that mean "this build cannot do it" are never damage: `unsupported`, `not supported`, `not configured`, `not been built in`, `insufficient memory`, `out of memory`, `out of order read`.** Measured: a healthy hierarchical JPEG says `VipsJpeg: Unsupported JPEG process: SOF type 0xc5` under the `VipsJpeg:` prefix. Anti-goal: good photos must keep their previews. If wrong: five attempts instead of one.
3. **Only `heif: Invalid input` counts as HEIF damage, not any `heif:` line,** for the same reason. If wrong: same cost.
4. **A cut TIFF stays retried.** Sharp says `unsupported image format` for it at `inspect`, which A3 forbids matching on a worker. It still makes no preview, and TIFF is not in the default `upload.formats`. If wrong: five attempts for a format most hosts do not accept.
5. **Sharp's pixel limit becomes `RESIZE_SOURCE_TOO_LARGE`, `false`, on the worker too,** with a message that keeps the words "pixel limit". The worker already treats the same code as terminal for `limits.sourcePixels`, and existing greps keep matching. If wrong: a host that raises the limit waits one cooldown, as it does for `sourcePixels`.
6. **The size guard runs at both decode sites, and `size` is added only to the snapshot's `original`, never to `signed`,** so the origin signature cannot change. If wrong: nothing regenerates either way; a stale `size` written by hand makes a damaged file retry five times.
7. **`limits.failOn` and `upload.verify` are required in a complete config, and a missing or wrong value is `RESIZE_CONFIG_INVALID`.** `undefined` would silently be Sharp's own `'warning'`, the level A2 rejected. Merging fills them for `createResizer` and `FrameworkResizer`. If wrong: a host passing a complete config to `new Resizer` adds two keys, named in the changelog.
8. **`limits.failOn` accepts all four Sharp levels, `'truncated'` included.** Refusing a real engine level gains nothing. If wrong: nothing.
9. **The docs recipe decodes at `failOn: 'error'`, what the worker now refuses, and describes `'warning'` as a wider, noisier second pass.** A flipped-bytes file can pass every level (measured), and the recipe says so. If wrong: a host misses some old garbled previews, which is disclosed.
10. **The task row holds the same `causeText` as the log line.** One text to search for, and the row's `String()` can no longer throw on a hostile value. If wrong: a host that parsed multi-line row text sees ` | `.
11. **The 1000-character cut applies to the cause text, not the whole line.** The ids in front must survive. If wrong: lines up to about 1200 characters.
12. **A line prints the error's `code` only when it is one token (`/^[\w.:-]{1,100}$/`), read under a guard, else `none`,** so `ENOENT` or `NoSuchBucket` shows, while a throwing getter cannot kill the loop (measured) and a multi-line code cannot forge a line (measured). If wrong: an odd code prints `none`; the cause text still holds the message.
13. **At shutdown, any handler rejection is added to the `info` line.** Telling an abort from a real failure needs a list of every abort-shaped error. If wrong: an `info` line says "it had failed: … incomplete" for a task only stopped by the shutdown.
14. **`RESIZE_PEER_MISSING` stays `true`,** against the research: a deploy that installs the package fixes it, which the A5 rule counts. Also `true`: `RESIZE_MEDIA_APPEND_RESULT_INVALID`, `RESIZE_MEDIA_REPLACE_RESULT_INVALID`, `RESIZE_ORIGINAL_STORAGE_REF_INVALID`, `RESIZE_PREVIEW_STORAGE_REF_INVALID`, and the errors `RESIZE_QUEUE_NOT_SERVED` and `RESIZE_LOCKS_REQUIRED` (their prewarm issues stay `false`, as today). If wrong: a task retries five times for a bug only a deploy fixes.
15. **Audited changes to `false`:** the classes `ResizeOriginalError` and `ResizeConfigError`, `RESIZE_TASK_MAX_ATTEMPTS`, `RESIZE_SVG_PUBLIC_PREVIEW`, `RESIZE_MEDIA_NO_ID`, `RESIZE_SIZE_INVALID`, and `RESIZE_WORKER_INCOMPLETE` under its condition, so a task whose only missing variants failed with `false` is dead on its first delivery while the variants it did store stay. A worker's start check already stops on a config error before the loop, so no `ResizeConfigError` site needs an explicit `true`. If wrong: a config error reaching a task dead-letters it, and the next read after the cooldown queues it again.
16. **`unconfirmed` carries `retryable: false` only for `RESIZE_MONGO_MODEL_MISSING` and `RESIZE_MONGO_MODEL_OUTDATED`.** A prewarm issue's `retryable` answers "does calling again help before someone fixes something", as `RESIZE_QUEUE_NOT_SERVED` already does. A database error stays retryable. If wrong: a prewarm caller stops retrying until its next run.
17. **Every code a task or an upload can hit is placed in the `retryable` table with its value; none is left unread.** Most rows trigger the error through real code. A row whose real run needs a task, a worker or a recorder names that test file instead, which must hold the code and assert the value. `NOT_READ` holds only codes that cannot reach a task or an upload's input, and the lists together must equal `RESIZE_ERROR_CODES`, so a new code, in a later phase too, must choose. If wrong: one more list to edit when adding a code.
18. **The index check asks the primary, in `verify()` too, and the background path still treats code 26 as unknown,** as A8 says. Measured: `collection.indexes({ readPreference: 'primary' })` works on a Mongoose collection whose connection prefers secondaries, and answers 26 for a missing collection. If wrong: a primary outage delays the line to a later add.
19. **The "checked" set is a module-level `WeakSet` per model,** like `loggedSchemaErrors`, so two queues on one model log once. If wrong: a test that reuses a model object must build a fresh one.
20. **Upload messages carry the helper's detail line rather than literally the first line,** so a cut AVIF says `heif: Invalid input…`, not `source: bad seek to 11724`. It serves A13's purpose. If wrong: nothing.
21. **The flush registers from a new protected `Resizer.onServicesBuilt()`, called once in `#ensureServices`.** `ready()` is not on every path: `generate`, `invalidate` and uploads call the private `#services()`. The research's `frameworkSource().own` misses an explicit config, which is read before the app exists. If wrong: one protected method on a public class.
22. **The sink is not wrapped for the flush,** so `resizer.metrics` stays the host's object. If wrong: nothing.
23. **`processTask` resolves `{ requested, rendered }`, and `ConsumerDeps.handle` widens to `Promise<unknown>`.** `Promise<void | { rendered: number }>` adds a biome warning (`noConfusingVoidType`). `generated.length` is `rendered`; a no-op path gives `0`. `variants 0 of 9` then marks a task that found everything fresh. If wrong: a custom `handle` returning something else still works, because only a number is read.
24. **`runWorker` and `runResizeWorker` resolve `Promise<boolean>`, `true` after a run and `false` when nothing was consumed, and the command returns it.** `false` covers the disabled path and the eager-only path (`resize worker: no Resizer has a task queue`, which keeps its `error` line): a process a deploy believes is a worker but that consumes nothing is the same mistake. The boolean is the smallest report: `runWorker` already returns early there. It is a small public change, named in the changelog. If wrong: a host calling either directly ignores the value.
24a. **Docs say "the command resolves `false`, so a CLI entry that forwards the result, as the framework docs require, exits 1", never "exits 1" alone.** `Cli.run` only returns the result; the `process.exit` line is in the host's entry. If wrong: nothing; a host whose entry ignores the result exits 0, and the docs say why.
25. **CI jobs get `timeout-minutes: 15`,** from `research-core.md`. Tests take about 31 s and a first mongod download is about 150 MB. If wrong: raise one number.
26. **The read-cost docs (M7 prose) stay in phase B (B11).** This phase only fixes statements that become false. If wrong: nothing.
27. **`svgload_buffer:` counts as damage.** An unsized SVG says `Input buffer has corrupt header: svgload_buffer: bad dimensions` (measured on Sharp 0.35.5 and 0.35.3). Without it, it would be a retryable `RESIZE_ORIGINAL_INSPECT_FAILED` at upload and five attempts on a worker, for a file that can never work. If wrong: a wrongly refused SVG, and `svgload_buffer: bad dimensions` is the only message of that prefix measured.
28. **Damage on a stored format no decoder of this process lists is never `RESIZE_SOURCE_DAMAGED`, at either stage.** `identify` turns it into `RESIZE_DECODER_MISSING`, and `decodeFailure` turns a failure at render into the retryable `RESIZE_SOURCE_DECODE_FAILED`. Sharp half-reading a host decoder's container during a rolling deploy must not dead-letter good media (A3; `identify(cutGif, limits, 'pdf')` measured). If wrong: five attempts for a really damaged file whose stored format has no decoder.
29. **Every read of a thrown value on the failure path is guarded, because a thrown value may be host code.** `codeText`, `isModuleError` and `notRetryable` in `src/helpers/log.ts`, `errorCodeLabel` in `src/metrics.ts`, and the console fallback of `logNeverThrow`, since `util.inspect` itself throws on `new Error('x', { cause: proxyWithThrowingTraps })` (measured). `causeText` already survives a throwing `toString`, `message`, `name` and `cause`, and such a Proxy (measured). A value whose brand or `retryable` cannot be read is retried. If wrong: a hostile value costs its attempts, and the loop survives.
30. **`'none'` restores 0.3.0's rendering, not all of 0.3.0.** `inspect` runs `metadata()` at Sharp's default level whatever `limits.failOn` says, so a file whose header cannot be read (a cut GIF or WebP) fails at every level, now at once rather than after five retries. A test pins it, and the docs say so. If wrong: a host at `'none'` sees a dead task earlier than it did.
31. **The docs say "`'error'` refuses a truncation that cuts image data; a cut TIFF is retried, not refused",** because a PNG missing only its last 8 bytes renders at `'error'` (measured), and A2's "every truncation" holds only for its matrix. If wrong: nothing.
32. **The terminal scan skips an `unconfirmed` add result.** It is not an error: prewarm reads its `retryable`, the worker never does. The scan cannot tie `causeCode:` to a code, so without the skip the guard fails. If wrong: a real terminal error written with `status: 'unconfirmed'` in its literal goes unread, which no error does.
33. **The flush registers one `shutdown` listener per event bus, with a set of sinks,** not one per sink: more than ten Resizers with their own default sinks would print `MaxListenersExceededWarning`. The set is keyed by the bus, so it cannot outlive it, and `src/architecture.test.ts` names it. If wrong: nothing.

In `src/helpers/log.ts`, which now imports `ResizeError` from `../errors.ts`. The bodies matter because no test can enumerate every hostile value:

```ts
const flat = (value: unknown): string =>
  String(value).replace(/\s*[\r\n]+\s*/g, ' | ');

/**
 * One line for a log or a task row: never throws, so a value that cannot be printed cannot stop the
 * worker loop, and a message cannot forge a second log line.
 */
export function causeText(error: unknown): string {
  let text: string;
  try {
    text = flat(error);
  } catch {
    return 'a thrown value that cannot be printed';
  }
  try {
    const cause = (error as { cause?: unknown } | null)?.cause;
    if (cause !== undefined) {
      const first = flat(cause).split(' | ')[0];
      if (!text.includes(first)) {
        text += ` (cause: ${first})`;
      }
    }
  } catch {
    // A cause that cannot be read or printed: the message alone is what there is.
  }
  return text.slice(0, 1000);
}

/** The error's code when it is one token, else `none`: a code can hold a line break too. */
export function codeText(error: unknown): string {
  try {
    const code = (error as { code?: unknown } | null | undefined)?.code;
    if (typeof code === 'string' && /^[\w.:-]{1,100}$/.test(code)) {
      return code;
    }
  } catch {
    // A getter or a Proxy trap that throws: no code to show.
  }
  return 'none';
}

/** `ResizeError.isResizeError` for a value that may be hostile: a trap that throws means no. */
export function isModuleError(error: unknown): error is ResizeError {
  try {
    return ResizeError.isResizeError(error);
  } catch {
    return false;
  }
}
```

```ts
// Reads the engine's error text, the only place it says what went wrong. A Sharp upgrade that
// changes a message makes src/decoders/sharp.test.ts fail, and until then costs five attempts
// instead of one. Never add `unsupported image format` to the damage list: on a worker it means a
// format this process has no decoder for, and a rolling deploy must not dead-letter good media.
const CORRUPT_HEADER = 'Input buffer has corrupt header:';
const SEEK_NOISE = /^source: bad seek to \d+$/;
const DAMAGE =
  /^(VipsJpeg:|vipspng:|webp2vips:|webp:|gifload_buffer:|svgload_buffer:|tiff2vips:|heif: Invalid input|glib: XML parse error)|Warning treated as error/;
// A healthy file this build cannot decode, or a failure that is not about the bytes.
const NOT_DAMAGE =
  /unsupported|not supported|not configured|not been built in|insufficient memory|out of memory|out of order read/i;

export function engineDetail(message: string): string {
  const body = message.startsWith(CORRUPT_HEADER)
    ? message.slice(CORRUPT_HEADER.length)
    : message;
  const lines = body.split('\n').map((line) => line.trim()).filter(Boolean);
  return lines.find((line) => !SEEK_NOISE.test(line)) ?? lines[0] ?? '';
}

export function isEngineDamage(message: string): boolean {
  const detail = engineDetail(message);
  if (detail === '') {
    return message.startsWith(CORRUPT_HEADER);
  }
  if (NOT_DAMAGE.test(detail)) {
    return false;
  }
  return SEEK_NOISE.test(detail) || DAMAGE.test(detail);
}

export function isUnsupportedBytes(message: string): boolean {
  return message.includes('unsupported image format');
}
```

```ts
async function verifyDecodes(
  { decoder, info }: IdentifiedOriginal,
  body: Buffer,
  config: ResizeConfig,
): Promise<void> {
  try {
    await decoder.render(body, { width: 16, height: 16 }, { limits: config.limits, source: info, frames: 1 });
  } catch (cause) {
    if (isModuleError(cause)) {
      if (hasErrorClass(cause, WIRING_ERRORS)) throw cause;
      if (cause.code === 'RESIZE_SOURCE_DAMAGED') {
        throw new ResizeOriginalError(`resize uploadOriginal: the image is damaged: ${damageDetail(cause)}`, { code: 'RESIZE_ORIGINAL_DAMAGED', cause });

      if (ORIGINAL_CODES.has(cause.code)) throw originalError(cause);
    }
    throw new ResizeOriginalError(`resize uploadOriginal: the decode check failed: ${engineDetail(messageText(cause)).slice(0, 200)}`, { code: 'RESIZE_ORIGINAL_VERIFY_FAILED', retryable: true, cause });
  }
}
```

`src/framework/app.ts`. The body matters because the order of listeners is the point: the framework's logger closes on the same event, and winston drops lines after close.

```ts
// Keyed by the app's event bus, so it cannot outlive it. One listener per bus, whatever the number
// of sinks: more than ten listeners print MaxListenersExceededWarning.
const flushing = new WeakMap<object, Set<ResizeMetrics>>();

/** Write the sink's open window on the framework's `shutdown`, before its logger closes. */
export function flushAtShutdown(sink: ResizeMetrics): void {
  const events = getApp().events as Partial<EventEmitter> | undefined;
  if (typeof events?.prependOnceListener !== 'function') {
    return;
  }
  const known = flushing.get(events);
  if (known) {
    known.add(sink);
    return;
  }
  const sinks = new Set([sink]);
  flushing.set(events, sinks);
  events.prependOnceListener('shutdown', () => {
    flushing.delete(events);
    for (const each of sinks) {
      try {
        void Promise.resolve(each.flush?.()).catch(() => {});
      } catch {
        // A host's sink must not break the host's shutdown.
      }
    }
  });
}
```
