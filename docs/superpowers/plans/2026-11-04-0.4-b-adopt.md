# 0.4.0 phase B: adoption Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A host with existing media can put it on the module in place, one entity at a time, and a new adopter gets working local storage from the scaffold (design rulings B1 to B11, including B2a).

**Architecture:** `hasOriginal` and `resizer.adoptOriginal` reuse the uploader's `identifyOriginal` and `verifyDecodes`; they write nothing. A new `limits.sourceBytes` bounds every read through an optional `download(ref, { maxBytes })`. The S3 driver reads a wider key rule while everything it writes stays strict. The rest is scaffold output, small removals and the guide.

**Tech Stack:** Node >= 24, TypeScript with type stripping, `node:test`, Biome, Sharp, `@aws-sdk/client-s3`, `@aws-sdk/s3-request-presigner`, mongoose and `mongodb-memory-server` for integration tests, `@adaptivestone/framework` 5.6.

**Spec:** `docs/design/2026-11-04-0.4.0.md`. Research (reuse it unless a ruling differs): `.superpowers/sdd/2026-11-04-0.4.0/research/research-adopt.md`, `adopt-prototype.diff`, `research-core.md` items 6 and 7.

## Review Focus

1. **URLs of stored previews must not change.** A key in the strict alphabet comes out of `publicUrl` byte for byte in all three URL forms (Task 2 test `a key in the upload alphabet comes out of publicUrl unchanged in all three URL forms`).
2. **A lone surrogate in a stored key.** Both `encodeURIComponent` and the SDK throw `URIError` on it (measured). It must be the typed refusal, never a raw `URIError` from `publicUrl`, which the read path calls (Task 2 refusal table).
3. **A host with `upload.maxBytes` above `limits.sourceBytes`.** It must not store originals that every task then refuses (Task 1 test `a body over limits.sourceBytes is refused at upload, naming that limit`).
4. **An S3 object over the limit.** The body is never read and the connection is released; a store that sends no length is still caught by the core (Task 1 tests on the fake endpoint and with a fake client).
5. **An empty `RESIZE_PUBLIC_BASE_URL`, and a `.gitignore` with CRLF line endings.** The first must not silently make URLs root-relative, the second must not get a duplicate rule (Task 5 tests `the … config writes the private root and an absolute URL from the environment`, which pins `||`, and `a .gitignore with CRLF line endings is read correctly`).

## Rulings

Each: what, why, cost if wrong.

1. **The S3 read rule also refuses lone surrogates.** `encodeURIComponent` and the SDK both throw `URIError` on them, measured. S3 keys are UTF-8, so such a key cannot exist. Cost: none.
2. **`publicUrl` encodes each `/` part with `encodeURIComponent` plus `!'()*`.** That is exactly what the SDK sends on the wire (34 hostile keys compared), and a quote in a URL could otherwise break a host's HTML attribute. The strict alphabet is unchanged by it. Cost: a CDN rule written against a literal `(` stops matching a host's own key.
3. **No key length check on reads.** A key over 1024 bytes gets S3's own error, is retried and dead-lettered. Cost: four extra requests for a key that cannot exist.
4. **The rule lives in `validateStoredKey` in `src/drivers/placement.ts`,** beside the strict rules; only the S3 driver calls it. Cost: none.
5. **The driver's over-limit error is `ResizeMediaError`,** code `RESIZE_SOURCE_TOO_LARGE`, `retryable: false`, without the key in its message, because a key may hold a client's file name and this line reaches logs. `RESIZE_STORAGE_NOT_FOUND` (phase A) does print the key, as `object not found: priv/none.png`: an operator needs it to find a lost file, and that code is retryable, so the `tryAgainLater()` branch of the catch sample in `AGENTS.md` does not answer a client with it. Cost: an operator reads the over-limit key from the media row; a host that answers with `err.message` on a retryable error can echo a client's file name.
6. **S3 checks `ContentLength` on the `GetObject` response, with no `HeadObject`.** One request and no new IAM permission. A response without a length is read, and the core's check catches it afterwards. Cost: a store that omits the length can still exhaust memory. S3 sends it.
7. **`uploadOriginal` also refuses a body over `limits.sourceBytes`,** as `RESIZE_ORIGINAL_TOO_LARGE`, naming that limit. Otherwise a host with a larger `upload.maxBytes` stores originals no task can read, as `limits.sourcePixels` already guards both paths. Cost: such a host raises one number.
8. **A complete config passed to `new Resizer({ config })` must hold `limits.sourceBytes`.** The validator gives no default; the merge gives it on every other path. The changelog says so. Cost: one line for a hand-wired host with literal `limits`, reported on first use.
9. **`adoptOriginal` applies B8 too.** A public object read by a decoder without `publicOriginals` is `RESIZE_ORIGINAL_PUBLIC_REFUSED`, the same exposure as a public SVG. Cost: a host adopting public PDFs sets one flag.
10. **New code `RESIZE_ORIGINAL_DOWNLOAD_FAILED`** (`ResizeStorageError`, `retryable: true`) for a non-module error from a driver during adoption. A module error passes unchanged. Cost: none.
11. **A `resize.adopt` timing metric, debug line only,** not in the summary. Adoption is a bounded script, not traffic. Cost: a host wanting counts keeps its own.
12. **The six internal `storageRef == null` sites stay.** `hasOriginal` is for hosts. Phase C edits those lines and nothing changes in behaviour. Cost: the rule stays repeated, as today.
13. **`S3Storage.fromConfig` also refuses `storage.publicUrl`** with `RESIZE_CONFIG_REMOVED_KEY`: a JavaScript host's config file has the same silent fall-through as the option. `publicUrl: undefined` is not refused, since nothing is lost. Cost: none.
14. **`''` for `rootDir` or `privateRootDir` is refused in the constructor too,** because a hand-wired host with an empty environment variable has the same hazard as a config file. Cost: none.
15. **The template uses `||`, not `??`, for `RESIZE_PUBLIC_BASE_URL`.** With `??` an empty variable gives root-relative URLs that work on one origin and 404 on another. Cost: an empty variable in production gives `localhost` URLs, which are at least obviously wrong.
16. **The development recipe imports `express` dynamically, inside the `NODE_ENV` guard.** A dev dependency is not installed in production, so a static import would crash boot. A repo test runs the recipe on a real framework `Server` (measured: no Mongo needed, a dummy DSN, about 0.7 s), and the module gains `express` as a dev dependency. Cost: that test fails if the framework changes what `startServer` needs, which is what it is for.
17. **`signedUrl` turns only a missing presigner itself into `RESIZE_PEER_MISSING`.** A missing package deeper in its tree stays the raw error, as `importDriver` does. Cost: none.
18. **The fake endpoint checks the path, not the SigV4 signature.** The SDK owns signing; real S3 stays the owner's check. Cost: a signature bug only real S3 would show, which that check covers.
19. **Phase A's names here are the real ones,** checked against `1339a98`. Cost: a later phase A commit that renames one fails the first test that uses it.
20. **`limits.sourceBytes` stays 256 MiB.** It holds a 50 MP TIFF at 8 bits per channel (143 MiB), not at 16 bits (286 MiB), which is refused. A long animated GIF or a raised `limits.sourcePixels` needs a higher limit. The docs say so, and every refusal message names `limits.sourceBytes`. Uploads stop at 25 MiB first, and the refusal is cheap and clear: dead at delivery 1, one number to raise, nothing regenerates. Cost: a host adopting 16-bit TIFFs gets dead tasks until it raises that number.
21. **The guide's backfill sample treats `RESIZE_STORAGE_NOT_FOUND` as final for that record:** it logs and skips it, and caps retries for anything retryable. The code stays `retryable: true` for a store that is catching up, but over old rows the file is gone, and a lost file must not loop for ever. A file this build cannot decode (`RESIZE_ORIGINAL_VERIFY_FAILED`, `true`) stops at the cap too. Cost: a record whose object arrives later stays skipped until the host runs it again.
22. **`RESIZE_ORIGINAL_STORAGE_REF_INVALID` is `false` at adoption and `true` at upload,** and the throw table says so. At adoption the caller passed no ref; at upload a driver returned nothing. Cost: a handler that branches on this code without reading `retryable` gets one of them wrong.
23. **The gate grows where exports change.** Tasks 1, 3, 4, 5 and 6 also run `npm run build` and `npm run smoke`, because `smokeTest.ts` holds its own list of the main entry's exports and the `packaging` CI job runs it, and Task 5 edits that file. Every task's final step lists its guards. Cost: a slower gate on those tasks.
24. **The `min-versions` failure on phase A's PR is fixed on the phase A branch,** separately; no step here covers it. Cost: phase B commits stay red on CI until that fix is in the stack.
25. **The adoption check decodes the first frame only,** as phase A's upload check does, and the docs say so. Measured: an animated WebP with bytes flipped at 75% passes adoption, and a worker with `animated: true` dead-letters it with `RESIZE_SOURCE_DAMAGED`. Cost: one dead task for such a file; decoding every frame would charge every host at attach time.
26. **The read warning also covers a sub-field projection that drops `original.storageRef`,** a phase A leftover taken into Task 4, because that projection looks not adopted. A lean row stays silent, as `notLoaded` already says. Cost: none measured; every existing pin stays green.

```ts
/**
 * A key already in a bucket, which the module only reads. It may hold a client's file name, so it
 * is not held to the alphabet of the keys the module writes. S3 keys are flat, and the SDK encodes
 * the key itself. Control characters, and the parts a URL or a proxy would resolve as a path, are
 * refused. A lone surrogate is not valid UTF-8, so no such key exists, and encoding it throws.
 */
export function validateStoredKey(key: string): string {
  if (
    !key.isWellFormed() ||
    /\p{Cc}/u.test(key) ||
    key.split('/').some((part) => part === '' || part === '.' || part === '..')
  ) {
    throw new ResizeSecurityError(
      "resize s3: invalid object key: it holds a control character, a '.' or '..' part, a leading '/' or an empty part",
      { code: 'RESIZE_STORAGE_KEY_INVALID' },
    );
  }
  return key;
}
```
