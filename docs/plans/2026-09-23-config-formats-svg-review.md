# Ограниченный план: конфигурация, форматы и SVG

Обновление по последующему решению пользователя: SVG теперь определяется через
`sharp().metadata()`, `saxes` и ручной XML-разбор удалены. Размеры берутся из Sharp
(включая `viewBox`), нечитабельные SVG отклоняются общей ошибкой загрузки.
Отдельного запрета DTD нет; санитизация остаётся обязанностью приложения.
Ниже сохранён исторический план; его требования к `saxes` и SVG-размерам заменены
этим решением. Конфигурация и схема хранения не меняются.

Статус: реализован 2026-09-23; итоговые проверки перечислены в отчёте исполнителя.
Основание: разбор исходников на коммите `a9566c1` и выделенных пользователем
фрагментов. Текста замечаний ревьюера на скриншотах нет; не приписывать ему
требования, которых нет в этом плане.

Отклонение от первоначального шага 4: прямой TypeScript-импорт типов
`saxes@5.0.1` не применён. Его `saxes.d.ts` выдаёт `TS2344` под используемым
TypeScript 7. Чтобы не включать `skipLibCheck` и не обновлять зависимость вне
задачи, сохранён `createRequire` с узким локальным типом трёх используемых
событий. Runtime-парсер и все XML-проверки остались прежними.

Ветка private storage не менялась в рамках этого плана. В целевом приложении
оригиналы хранятся в приватном бакете. В следующей задаче добавлено поле
`Original.publicCopy`: приложение сохраняет оригинал, загружает те же очищенные
байты как публичную копию и записывает её locator. `resolve()` отдаёт ссылку на
копию только после подтверждения публичности драйвером storage.

## Какая зависимость уже добавлена и зачем

- `saxes` — прямая production-зависимость, диапазон в `package.json`:
  `^5.0.1`, версия в `package-lock.json`: `5.0.1`.
- `xmlchars` — транзитивная зависимость `saxes`, версия в lock-файле `2.2.0`.
  Содержит проверки классов допустимых символов XML. Прямо из нашего кода
  её импортировать не нужно.
- `saxes` читает XML и выдаёт события открытия тегов, DTD и ошибок синтаксиса.
  В `uploadOriginal()` это позволяет проверить структуру XML и корень `svg`,
  прочитать атрибуты размеров без рендеринга изображения.
- Исходные байты SVG передаются в storage без изменения. Парсер не является
  SVG-рендерером, оптимизатором или санитайзером. Корректность XML не означает
  отсутствие скриптов, опасных ссылок или полную валидность по спецификации SVG.
- Определение формата и полная проверка XML — разные задачи. Само требование
  сохранять SVG или распознавать формат ещё не обосновывает полный XML-парсер.
  Его конкретная функция здесь: отвергать повреждённый XML, неправильный корень
  и DTD до записи в storage. Эта гарантия уже описана в README, раздел Original
  upload, и проверяется тестами. Это факт о текущем контракте, а не доказательство,
  что пользователю изначально была нужна такая дополнительная проверка.
- Цена решения: дополнительный пакет с транзитивной зависимостью и разбор XML
  при загрузке. Не утверждать, что цена нулевая или что парсер обеспечивает
  полную безопасность SVG. Размер и скорость не оценивались бенчмарком.
- Критерий необходимости: если модуль обязан сам проверять структуру переданных
  SVG, использовать готовый XML-парсер проще, чем поддерживать собственный.
  Если приложение гарантирует уже проверенный SVG, а модуль должен только его
  сохранить, повторный XML-разбор может быть лишним. Удаление этой проверки
  тогда требует отдельного решения о контракте uploadOriginal и его тестах;
  не заменять её самодельным парсером или regex под видом эквивалентной проверки.
- Решение для ограниченного рефакторинга в этом плане: сохранить нынешнюю
  гарантию проверки XML и оставить обе зависимости в текущих версиях. Это
  предложение сохранить совместимость; пользователь пока не поручал удалять
  проверку XML или менять ответственность uploadOriginal. Не выполнять
  установку, обновление, замену или удаление пакетов. `package.json` и
  `package-lock.json` не менять. `saxes` уже поставляет собственный `saxes.d.ts`.

## Шаг 1. Исправить выбор выходных форматов

Файлы: `src/resizeConfig.ts`, `src/config/resize.test.ts`.

Сейчас `requiredFormats()` при `webpAvifOnly: true` возвращает фиксированные
`['webp', 'avif']`, даже когда приложение выбрало только `['webp']`.

Сначала добавь регрессионные тесты, затем исправь функцию:

1. При выключенном/отсутствующем флаге возвращать `config.formats` как сейчас.
2. При включённом флаге удалять только `jpeg` из `config.formats`.
   Не добавлять форматы, не сортировать, не удалять дубликаты, не менять
   входной массив.
3. Если результат пустой, выбрасывать существующий `ResizeConfigError`
   с существующим кодом `RESIZE_CONFIG_FORMATS_INVALID` и понятным сообщением.
4. В `getResizeConfig()` после текущей проверки полей вызвать `requiredFormats()`
   для проверки непустого результата. Ошибка должна обнаруживаться при
   конструировании Resizer. Не заменять `config.formats` результатом фильтрации.
5. Сам публичный `requiredFormats()` также должен отвергать пустой результат.
   Не добавлять ему отдельный универсальный валидатор входных объектов.
6. Не удалять и не переименовывать `webpAvifOnly`, не добавлять предупреждения
   о deprecated. Параметры `opts.formats` у других операций не трогать.

Обязательные случаи:

| `formats` | `webpAvifOnly` | Результат |
|---|---|---|
| `['jpeg', 'webp', 'avif']` | `true` | `['webp', 'avif']` |
| `['webp']` | `true` | `['webp']` |
| `['avif']` | `true` | `['avif']` |
| `['avif', 'jpeg', 'webp']` | `true` | `['avif', 'webp']` |

| `['jpeg']` | `false` или отсутствует | `['jpeg']` |

## Шаг 3. Сделать настройку через конфиг приложения проще

Файлы: `src/scaffold/templates/resize.config.ts.tpl`,
`src/scaffold/command.test.ts`, `src/original.ts`, `src/config/resize.test.ts`.

Сохранить действующую цепочку:

```text
framework объединяет конфиг приложения и конфиг окружения
  -> getApp().getConfig('resize')
  -> getResizeConfig() дополняет дефолтами пакета и проверяет
  -> операция использует полученный конфиг
```

Framework не подмешивает дефолты этого npm-пакета автоматически. Поэтому
`deepmerge` внутри `getResizeConfig()` нужен и остаётся. Массивы должны
заменяться целиком, вложенные объекты — дополняться. Не добавлять второй
механизм получения настроек и не передавать конфиг в публичный конструктор.

Точные изменения:

1. В scaffold-конфиге оставить default-объект с `mediaModelName: 'File'`.
   Убрать runtime-импорт `defaultResizeConfig` и spread дефолтов.
2. Для проверки формы использовать уже экспортируемые типы:
   `import type { DeepPartial, ResizeConfig } from '@adaptivestone/framework-module-resize';`
   и `satisfies DeepPartial<ResizeConfig>` на default-объекте.
3. Примеры переопределений оставить комментариями без spread:
   `formats: ['webp']`, `upload: { maxBytes: 10 * 1024 * 1024 }`,
   `encode: { quality: { avif: 55 } }`,
   `worker: { enabled: true, concurrency: 4 }`.
   Worker по умолчанию не включать.
4. В тесте scaffold заменить ожидание наличия `...defaultResizeConfig`.
   Проверить, что созданный конфиг импортируется, содержит `mediaModelName`,
   а после передачи через fake app и `getResizeConfig()` получает дефолты.
   Убедиться, что импорт конфига не требует готового app singleton.
5. В `uploadOriginalImpl()` уже есть прочитанный `config`.
   Передать его вторым аргументом во внутренний `prepareOriginal(body, config)`
   с типом `ResizeConfig`; удалить чтение `getResizeConfig()` внутри helper.
   Публичную сигнатуру `uploadOriginal()` не менять.
6. Сохранить тесты частичных вложенных переопределений, замены массивов,

`getResizeConfig()` по-прежнему читает настройки при вызове. Конструктор

Старый публичный `config/resize.js` и compatibility-файл сохраняются полностью.

## Шаг 4. Упростить типизацию SVG-парсера и исправить размеры

Файлы: `src/original.ts`, `src/original.test.ts`.

Точные изменения:

1. Использовать `import { SaxesParser, type SaxesTagNS } from 'saxes'`.
   Удалить `createRequire`, интерфейсы `StrictXmlTag` / `StrictXmlParser`
   и приведение типа конструктора. Для корня использовать `SaxesTagNS`.
2. Оставить `new SaxesParser({ xmlns: true })`, разбор всего документа,
   обработчики ошибок и запрет DTD. Не заменять XML-парсер регулярным выражением.
3. Проверять `local === 'svg'` без `toLowerCase()`. Сохранить существующее
   принятие правильного SVG namespace и legacy-документа без namespace.
   `<svg:svg>` с правильным URI принимается, `<SVG>` — отвергается с
   существующим `RESIZE_ORIGINAL_NOT_SVG`.
4. `width` получать только из `parsePixelLength(attribute('width'))`,
   `height` — только из `parsePixelLength(attribute('height'))`.
5. Удалить fallback на `viewBox` и ставший неиспользуемым `parseViewBox()`.
   Не вычислять вторую сторону по пропорции, не добавлять `aspectRatio`,
   не разбирать CSS и не расширять поддержку единиц измерения.
6. Отсутствующий/неподдерживаемый размер не записывать в `Original`:
   ни `0`, ни `null`, ни угаданное число. Сохранять текущую условную запись полей.
7. `decodeXmlCandidate()`, поддерживаемые кодировки, лимит байтов, порядок
   проверки allowlist, storage-вызов и сохранение исходных байтов не менять.

Причина изменения размеров: `viewBox` задаёт прямоугольник координат и может
определять пропорции, но сам по себе не задаёт пиксельные width/height.
Основание: [SVG 2, intrinsic sizing](https://www.w3.org/TR/SVG2/coords.html#IntrinsicSizing).

Сначала изменить ошибочные ожидания существующих тестов и убедиться,
что они падают на старом коде. Затем внести исправление. Обязательные случаи:

| Вход | Ожидание для `Original` |
|---|---|
| `width="120px" height="80"` | `width: 120`, `height: 80` |
| Только `viewBox="0 0 240 100"` | оба поля отсутствуют |
| `width="120px" height="50%" viewBox="0 0 240 100"` | `width: 120`, `height` отсутствует |
| Только `width="120"` и `viewBox` | `width: 120`, `height` отсутствует |
| Процентные/относительные обе стороны | оба поля отсутствуют |
| `<SVG xmlns="http://www.w3.org/2000/svg"/>` | ошибка до storage |
| `<svg:svg xmlns:svg="http://www.w3.org/2000/svg"/>` | принят |
| `<svg width="13" height="8"/>` без namespace | прежнее поведение сохранено |

Сохранить существующие проверки повреждённого XML, нескольких корней,
неверного namespace, DTD, неизвестных сущностей и кодировок; добавить недостающий
случай неверного namespace, если его нет. Стандартные XML-сущности, комментарии
и CDATA по-прежнему принимаются. Сохранить проверки исходных байтов и отсутствия
задач очереди. Сохранить успешные тесты JPEG/PNG/WebP/AVIF и анимации.

временное приложение и проверяет публичные импорты и scaffold. Это важно после

Не запускать дополнительно `npm run build`, если сборка внутри smoke уже прошла.
Если smoke недоступен из-за среды, отдельно выполнить `npm run build` и честно
сообщить, что проверка установленного пакета осталась невыполненной.
Не считать успешную сборку заменой smoke.

Не запускать автоисправление форматирования на всём репозитории. Исправлять
только затронутые файлы. Ошибки в посторонних областях зафиксировать отдельно.
Не утверждать, что проверки прошли, если команда не запускалась, упала или
нужные случаи были пропущены. Не повторять прошедшие проверки без новых изменений.

## Критерии готовности и отчёт исполнителя

- Пользовательский список форматов соблюдается; лишний AVIF не появляется.
- MIME и расширения прежние, их runtime-таблица больше не дублируется.
- Конфиг приложения содержит только overrides; дефолты применяются модулем.
- Нет повторного получения конфига внутри подготовки одного оригинала.
- SVG остаётся SVG, а `viewBox` не выдаётся за пиксельные размеры.
- `saxes` используется через совместимый узкий runtime-адаптер; XML-проверки не ослаблены.
- Публичные экспорты, зависимости, схемы и поведение очередей не изменены.
- Изменённые файлы находятся в разрешённом списке.
