# SVG как вход для растровых previews

## Решение

Пользовательский SVG сохраняется без изменения как приватный `original`. Воркер читает его через Sharp и создаёт те же размеры и форматы previews, что и для JPEG/PNG. Сейчас выходной каталог — JPEG, WebP, AVIF. Публичная выдача использует только готовые растровые previews; при их отсутствии возвращает состояние ожидания и ставит задачу по обычным правилам. Собственный XML-парсер и очиститель SVG не нужны. Проверка формата и размеров через `sharp().metadata()` при загрузке остаётся.

## Реализация

1. Удалить SVG-исключения из `processTask`, `generate`, `resolve`, `prewarm`, `enqueueRequired` и `isCatalogCovered`. Убрать `svgPublicCopy.ts`. Запретить исходному SVG проходить через общий shortcut «оригинал уже подходит» даже при наличии подписанного URL или старого `publicCopy`.
2. Использовать `generatePreviews` и существующие queue/locks/retry для SVG. При растеризации мелкого SVG учитывать целевой размер через Sharp `density`, ограничивать промежуточное число пикселей и время обработки; проверять фактические выходные байты, MIME и размеры. Не расширять перечень форматов автоматически.
3. Не допускать публичной загрузки SVG через `uploadOriginal`. Приватная загрузка не должна молча попадать в публичный S3 bucket. В локальном драйвере разместить новые originals вне каталога, который отдаёт nginx; старые `.svg` URL закрыть правилом nginx. Старые растровые оригиналы в публичном каталоге оставить доступными для существующего `original-fits` shortcut до миграции.
4. На бэке оставить интеграцию новых previews для аватаров. Убрать использование `original.publicCopy` и обновить описание в AGENTS/README/resize notes. Event/Boat пока используют свой legacy-путь.
5. Старые публичные SVG-копии не считать готовыми previews. После обновления кода и остановки старых воркеров поставить существующие SVG на повторную обработку. Проверить публичные объекты и CDN, затем закрыть прежние SVG-копии. Удаление поля из старых документов не требуется для начала выдачи previews.
6. Проверить новый SVG, старый SVG с `publicCopy`, отсутствие прямой выдачи оригинала, реальное JPEG/WebP/AVIF содержимое, качество малого SVG, ошибки и повтор задачи. Проверить конфигурацию и тесты модуля и бэка. Модуль получает версию `0.4.0`; после её публикации обновить установленный пакет и lockfile в бэке. До выпуска пакет для локальных тестов берётся из соседнего checkout. Не публиковать пакет и не деплоить без отдельной задачи.

## Критерий готовности

Для пользовательского SVG приватные исходные байты остаются доступны воркеру, а URL, возвращаемые приложению, указывают только на готовые растровые previews. Текущий формат, очередь и размеры для обычных изображений сохраняют существующее поведение. Локальное хранилище не раздаёт приватный SVG через nginx. Ранее созданные публичные SVG-копии учитываются отдельно при переходе.
