# 0.4.1: what a host must know from the first production use

Status: approved by the owner on 2026-11-21 ("we can go with version A … go from it"), as the first half
of the split: 0.4.1 holds docs and test fixes only, and 0.5.0 holds the features. Input: a problems
report from a host's production use of 0.4.0, checked item by item against `3d62c4e`. The check and
the owner's decisions are kept in the controller's ledger; this file holds what 0.4.1 changes.

## Why

A host found 18 problems. Checking them showed that several already have a working answer in 0.4.0
that the docs do not give, or give in a place a host does not look:

- a pipeline change that blurs or removes something keeps the old render served (as stale) until the
  new one is stored, and for as long as the new pipeline fails; renaming the pipeline avoids that;
- a worker's start can already run a host's own precondition, by extending the scaffolded command;
- a test runner that evaluates the construction module twice can reuse the first Resizer;
- one `doc as MediaLike` is enough, and the typed model paths need no cast;
- the fs driver has no `signedUrl`;
- previews become visible before their task is marked `completed`;
- a worker finishes its task in progress on SIGTERM, for up to `taskTimeoutMs`;
- the module checks only the bytes it is given, after the host's body parser has accepted them;
- a migration must check preview coverage, not only that an original exists.

Two tests in `src/regenerate.test.ts` also fail under load, for a reason that differs from the one the
report gives.

## Goals

1. Each fact above has one home in the docs, and the others link to it.
2. The two timing-dependent tests pass whatever the time the work before the variant pool takes.
3. Nothing a host runs changes: no code path in `src/` other than tests and comments.

## Non-goals

Everything that changes behaviour or an API is 0.5.0: deletion, fencing, a bounded stop, hiding stale
rows, the non-retryable re-run fix, escalating cooldowns, redrive, stats, `Pipeline.verify`, per-call
upload limits, step deadlines, a GCS driver, S3 `cacheControl`, a media input type, `getOrCreate`.

## Rulings

1. **Redaction changes rename the pipeline.** The Freshness section of the README says what a `version`
   bump does while its replacement is pending or failing, and that a change which must stop the old
   image from being served (a blur, a redaction, a removed watermark) renames the pipeline instead, so
   old rows belong to another pipeline and are never served. It also gives the central alternative: a
   `formatPublicUrls` tap that drops `stale` entries of that pipeline, with its caveat (a tap that throws
   before it drops them leaves them served). `AGENTS.md` gets one rule line that links there. If wrong:
   a host that wanted the stale render keeps a few more placeholders after a rename.
2. **An unregistered pipeline is called out where pipelines are registered.** The README already says it
   serves every stored row as fresh; `AGENTS.md`'s "Register every pipeline" rule adds why (a process
   that reads a pipeline it does not know serves rows it cannot judge). If wrong: one more clause.
3. **Host preconditions at worker start: extend the command, never copy it.** The README's worker section
   shows the scaffolded command extended with a check before `super.run()`, and says `--check` still
   passes. The `AGENTS.md` rule "do not vendor or fork them" says extending is allowed. If wrong: 0.5.0's
   `Pipeline.verify` replaces it, and the recipe still works.
4. **A second evaluation reuses the first Resizer.** The README (near the duplicate-name rule) shows the
   guarded construction for runners that evaluate `src/resizer.ts` twice: `getResizer(name)` first, and
   `new FrameworkResizer(…)` only when it throws `RESIZE_NO_RESIZER`. It also says why a `globalThis`
   holder is not needed. If wrong: 0.5.0's `getOrCreate` replaces it.
5. **One cast, never two.** The README's `MediaLike` paragraph (before `## Config reference`, so its length
   must not grow the npm page's cut) says one `as MediaLike` is enough and `as unknown as` hides real
   mismatches. If wrong: nothing.
6. **The fs driver states that it has no `signedUrl`.** One sentence in the `LocalFsStorage` section, with
   what a development host does instead. If wrong: nothing.
7. **Rows before `completed`.** The README's Operations says rows are written before the task is marked
   `completed`, so a test or a monitor that waits for the task waits on its status. If wrong: nothing.
8. **Stopping a worker.** The README's Operations gives the stop sequence (stop claiming, finish the task
   in progress up to `taskTimeoutMs`, observers up to 5 s, the metrics flush up to 5 s), what a SIGKILL
   before the end costs (the lease runs out, so up to `leaseMs` of delay and one counted attempt; files
   uploaded but not recorded stay in storage), and how to size a container's stop timeout. If wrong: a
   host sizes a timeout too long.
9. **Body-parser limits.** The guide's upload section tells a host to set the framework's body and
   multipart limits at or below `upload.maxBytes`, and to cap the file count; the module checks only the
   bytes it is handed. If wrong: nothing.
10. **Migrations check coverage.** The guide's adopting section says a resumable migration checks
    `isCatalogCovered`, not only `hasOriginal`, and handles `generate()`'s `failed > 0`. If wrong:
    nothing.
11. **Dead tasks run again after the cooldown, whatever the error.** The README's Coordination says so
    plainly until 0.5.0 changes it, and the code comments that promise "inspection and replay" point at
    the README's replay recipe. If wrong: nothing.
12. **The two tests stop depending on the delivery's timing.** `taskTimeoutMs` rises to a value no
    delivery reaches before its variant runs (about 2 s), and the tap waits on a promise the test
    releases, instead of a fixed 400 ms. The test asserts that the first delivery stored its row before
    its timeout. If wrong: the test runs about 2 s longer.
13. **Versions.** `npm version 0.4.1 --no-git-tag-version` and a CHANGELOG section. The guide gets its own
    PR on the docs-site repository. Public docs never name the host.

## Constraints

- `npm test`, `npm run check`, `npm run types:check`, `npm run build` and `npm run smoke` stay green.
- The doc guards hold: `AGENTS.md` at most 5,000 words, the README's npm cut (65,536 characters) still
  past `## Config reference`, and every link and anchor resolves.
